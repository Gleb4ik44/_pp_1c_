# Тест-план: функциональное тестирование

## Идентификатор

ТП-СУ-РГВ-ФУНК-2026 — тест-план функционального тестирования подсистемы складского учета, автор Румянцев Г.В.

## Введение

Один из 4 методов тестирования подсистемы складского учета (наряду с позитивным, негативным и смоук — см. `testing/README.md`). Проверяет не просто «отработало без ошибки», а что бизнес-логика соответствует требованиям, описанным в теоретической части ВКР — то есть система делает именно то, что от нее ожидается по постановке задачи.

## Объект тестирования

Документ «Приходная накладная» (заполнение на основании документа «Заказ поставщику»); документ «Расходная накладная» (расчет себестоимости по средневзвешенной цене); отчет «ОстаткиТоваровНаСкладах» (корректность итоговых сумм).

## Функции, которые тестируются этим методом

Автозаполнение приходной накладной данными из заказа поставщику; расчет себестоимости при списании как средневзвешенной цены по нескольким приходам; соответствие строки «Итого» отчета сумме строк детализации.

## Функции, которые не тестируются этим методом

Реакция на некорректные данные — зона негативного тестирования (`test-plan-negativ.md`); базовая работоспособность без ошибок — зона смоук-тестирования (`test-plan-smoke.md`).

## Критерии начала тестирования

- Информационная база восстановлена и открывается в режиме 1С:Предприятие без ошибок.
- Для TC-05 в базе должно быть не менее двух приходов по одному товару с разной ценой — иначе проверить среднее взвешенное невозможно.
- Для TC-02 должен существовать проведенный документ «Заказ поставщику».

## Критерии окончания тестирования

Все тест-кейсы из `test-cases-funkc.md` (TC-02, TC-05, TC-09) выполнены минимум один раз, результат сверен вручную (расчет себестоимости и суммы отчета проверены отдельным ручным подсчетом, а не только визуально).

## Критерии приостановки и возобновления тестирования

Тестирование приостанавливается при обнаружении дефекта серьезности S1 или S2 — в первую очередь, расхождения в расчете себестоимости было бы дефектом такого уровня, поскольку напрямую искажает финансовый результат.

## Результаты тестирования

Этот тест-план и `test-cases-funkc.md` с зафиксированным результатом по каждому кейсу.

## Задачи тестирования

Подтвердить, что бизнес-логика, заявленная в теоретической части работы (автозаполнение документов на основании друг друга, расчет себестоимости по методу средневзвешенной цены, корректность аналитической отчетности), реализована так, как описана, а не только «выглядит рабочей» на уровне отсутствия ошибок выполнения.

## Ресурсы

Тестовая копия информационной базы с несколькими приходами по одному товару по разным ценам (для проверки расчета себестоимости) и проведенным заказом поставщику (для проверки автозаполнения).

## Обязанности и роли

Тестирование выполняется автором работы, Румянцевым Г.В.

## Расписание

В рамках общего периода тестирования — с 20.08.2026 по 23.08.2026.

## Оценка рисков

Главный риск — проверить расчет себестоимости на данных, где среднее взвешенное случайно совпадает с простым средним, и не заметить ошибку в логике. Снижается тем, что в TC-05 сознательно используются приходы с существенно различающейся ценой, а не близкими значениями.

## Согласования

Результаты тестирования рассматриваются руководителем ВКР при проверке главы 3, до допуска к защите.
