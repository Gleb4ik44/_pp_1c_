# Тест-план: негативное тестирование

## Идентификатор

ТП-СУ-РГВ-НЕГ-2026 — тест-план негативного тестирования подсистемы складского учета, автор Румянцев Г.В.

## Введение

Один из 4 методов тестирования подсистемы складского учета (наряду с позитивным, смоук и функциональным — см. `testing/README.md`). Проверяет реакцию системы на некорректные, граничные и нештатные входные данные и условия — то, что позитивное тестирование намеренно не покрывает.

## Объект тестирования

Документ «Расходная накладная» (процедура `ОбработкаПроведения`); общий модуль «РаботаСВалютами» (сценарий недоступности внешнего сервиса); общий модуль «Вспомогательный» (функция `ПолучитьЦенуНоменклатуры`); отчет «ОстаткиТоваровНаСкладах» (граничный случай отображения при нестандартном масштабировании экрана).

## Функции, которые тестируются этим методом

Попытка отгрузки товара сверх фактического остатка; поведение загрузки курсов валют при недоступности внешнего сервиса; получение цены номенклатуры, когда цена не установлена на дату; отображение отчета об остатках при масштабе экрана Windows выше 100%.

## Функции, которые не тестируются этим методом

Штатные, корректные сценарии — это зона позитивного тестирования (`test-plan-pozitiv.md`).

## Критерии начала тестирования

- Информационная база восстановлена и открывается в режиме 1С:Предприятие без ошибок.
- Пройдены соответствующие позитивные кейсы (например, TC-01 перед TC-04) — иначе негативный сценарий может дать ложный результат по причине, не связанной с проверяемой логикой.
- Известен точный остаток товара на складе на момент запуска сценария с превышением отгрузки.

## Критерии окончания тестирования

Все тест-кейсы из `test-cases-negativ.md` (TC-04, TC-07, TC-08, TC-10) выполнены минимум один раз, по расхождениям заведены записи в `bug-report.md`.

## Критерии приостановки и возобновления тестирования

Тестирование приостанавливается при обнаружении дефекта серьезности S1 или S2. Дефект, найденный в рамках этого метода (BUG-01, серьезность S4), к остановке тестирования не привел — тестирование продолжилось по остальным негативным кейсам.

## Результаты тестирования

Этот тест-план, `test-cases-negativ.md` с зафиксированным результатом по каждому кейсу и запись BUG-01 в `bug-report.md`.

## Задачи тестирования

Подтвердить, что система не допускает операций, нарушающих бизнес-правила (отгрузка сверх остатка), и корректно, без падения, обрабатывает нештатные внешние условия (недоступный сервис курсов, отсутствующая цена, непривычный масштаб экрана) — то есть ведет себя предсказуемо, а не аварийно, при отклонении от идеальных условий.

## Ресурсы

Тестовая копия информационной базы с известным, заранее зафиксированным остатком по тестовому товару; возможность временно отключить сеть для сценария TC-07; виртуальная машина с изменяемым масштабом экрана Windows для сценария TC-10.

## Обязанности и роли

Тестирование выполняется автором работы, Румянцевым Г.В.

## Расписание

В рамках общего периода тестирования — с 20.08.2026 по 23.08.2026, после позитивных сценариев.

## Оценка рисков

Главный риск — не покрыть все реальные граничные случаи. Смягчается тем, что выбранные кейсы покрывают ключевое бизнес-правило (контроль остатка при отгрузке) и обе внешние зависимости системы (сетевой сервис курсов, отсутствие цены), а не произвольный набор проверок.

## Согласования

Результаты тестирования рассматриваются руководителем ВКР при проверке главы 3, до допуска к защите.
