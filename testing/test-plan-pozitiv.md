# Тест-план: позитивное тестирование

## Идентификатор

ТП-СУ-РГВ-ПОЗ-2026 — тест-план позитивного тестирования подсистемы складского учета, автор Румянцев Г.В.

## Введение

Один из 4 методов тестирования подсистемы складского учета (наряду с негативным, смоук и функциональным — см. `testing/README.md`). Позитивное тестирование проверяет, что при корректных, штатных входных данных операции выполняются так, как задумано, без искусственного создания ошибочных ситуаций.

## Объект тестирования

Документы «Приходная накладная», «Расходная накладная»; общий модуль «РаботаСВалютами» (загрузка курсов валют при доступном внешнем сервисе); справочник «Номенклатура».

## Функции, которые тестируются этим методом

Проведение приходной накладной по штатному сценарию; отгрузка товара расходной накладной при достаточном остатке; загрузка курсов валют при доступном сервисе cbr-xml-daily.ru; создание нового элемента справочника «Номенклатура».

## Функции, которые не тестируются этим методом

Реакция системы на ошибочные и граничные данные — это зона ответственности негативного тестирования (`test-plan-negativ.md`), не позитивного.

## Критерии начала тестирования

- Информационная база восстановлена и открывается в режиме 1С:Предприятие без ошибок.
- В справочниках заведены минимум одна номенклатурная позиция, один склад, один контрагент.
- Регистр «ОстаткиНоменклатуры» не содержит ошибочных отрицательных остатков от предыдущих прогонов.

## Критерии окончания тестирования

Все тест-кейсы из `test-cases-pozitiv.md` (TC-01, TC-03, TC-06, TC-12) выполнены минимум один раз, результат зафиксирован в статусе кейса.

## Критерии приостановки и возобновления тестирования

Тестирование приостанавливается при обнаружении дефекта серьезности S1 или S2 (см. общие критерии в `bug-report.md`). По позитивным сценариям такие дефекты маловероятны по определению метода, но правило действует одинаково для всех 4 блоков.

## Результаты тестирования

Этот тест-план и `test-cases-pozitiv.md` с зафиксированным результатом по каждому кейсу.

## Задачи тестирования

Подтвердить, что базовые складские операции (приход, отгрузка, автозагрузка курсов, ведение справочника номенклатуры) работают на корректных данных без ошибок — это необходимое условие для того, чтобы негативные и функциональные тесты вообще имели смысл: нет смысла проверять реакцию на ошибку в системе, которая не работает даже в штатном режиме.

## Ресурсы

Тестовая копия информационной базы (см. `testing/README.md` общего тест-плана про окружение), доступ в интернет для сценария загрузки курсов валют.

## Обязанности и роли

Тестирование выполняется автором работы, Румянцевым Г.В. Отдельная роль тестировщика не выделяется.

## Расписание

В рамках общего периода тестирования — с 20.08.2026 по 23.08.2026, позитивные сценарии прогонялись первыми, до негативных и граничных — типовой порядок «сначала happy path».

## Оценка рисков

Основной риск позитивного тестирования — использовать нетипичные тестовые данные, которые случайно замаскируют проблему (например, слишком «круглые» числа). Снижается использованием чисел, близких к реальным (дробные количества, цены с копейками).

## Согласования

Результаты тестирования рассматриваются руководителем ВКР при проверке главы 3, до допуска к защите.
