# Тест-кейсы: функциональное тестирование

Формат: ID, объект, метод, предусловия, шаги, ожидаемый результат. Фактический результат и ссылка на баг-репорт (если есть расхождение) фиксируются в колонке «Статус» по мере прогона.

Относится к `test-plan-funkc.md`.

## TC-02 — Приходная накладная: заполнение на основании заказа поставщику

- **Объект:** Документ «Приходная накладная», обработчик `ОбработкаЗаполнения`
- **Метод:** Функциональное
- **Предусловия:** Существует проведенный документ «Заказ поставщику» со списком номенклатуры.
- **Шаги:** Создать приходную накладную на основании заказа поставщику.
- **Ожидаемый результат:** Поля «Контрагент», «Договор», «ВидЦены» и табличная часть автоматически заполняются данными из заказа.
- **Статус:** пройден

## TC-05 — Расходная накладная: расчет себестоимости по средневзвешенной цене

- **Объект:** Документ «Расходная накладная», запрос расчета себестоимости
- **Метод:** Функциональное
- **Предусловия:** По товару было несколько приходов по разной цене.
- **Шаги:** Провести расходную накладную на количество, включающее остатки от разных приходов.
- **Ожидаемый результат:** Себестоимость в движении регистра «Выручка» рассчитывается как средневзвешенная от стоимости остатка на момент проведения, без «увода в минус» суммовых остатков.
- **Статус:** пройден

## TC-09 — Отчет «Остатки товаров на складах»: корректность итогов

- **Объект:** Отчет «ОстаткиТоваровНаСкладах»
- **Метод:** Функциональное
- **Предусловия:** По нескольким товарам есть движения на складе.
- **Шаги:** Сформировать отчет за период, включающий все движения.
- **Ожидаемый результат:** Строка «Итого» равна сумме количеств по всем строкам детализации; данные совпадают с ручным подсчетом по регистру.
- **Статус:** пройден
