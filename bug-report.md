# Баг-репорт

Формат записи: идентификатор, компонент, описание, шаги воспроизведения, ожидаемое/фактическое поведение, серьезность (S1 — критическая, блокирует работу; S2 — высокая; S3 — средняя; S4 — низкая; S5 — косметическая), приоритет исправления, статус, комментарий.

## BUG-01 — Некорректная ширина колонок в отчете «Остатки товаров на складах» при масштабировании экрана Windows выше 100%

- **Компонент:** Отчет «ОстаткиТоваровНаСкладах», форма отчета (макет оформления, встроенная диаграмма)
- **Обнаружен в тест-кейсе:** TC-10
- **Шаги воспроизведения:**
  1. Установить масштаб экрана Windows выше 100% (например, 175% или 200% — актуально для запуска на Retina-дисплее через виртуальную машину).
  2. Сформировать отчет «Остатки товаров на складах» по товару с суммой от шести значащих цифр.
- **Ожидаемое поведение:** Значения в колонках «Цена» и «Сумма» отображаются полностью.
- **Фактическое поведение:** Колонки отображают «####» вместо значений — платформа некорректно рассчитывает необходимую ширину колонки при нецелом масштабировании экрана. При масштабе экрана 100% отчет формируется корректно на тех же данных.
- **Причина:** Особенность работы платформы 1С:Предприятие с автоматическим расчетом ширины колонок табличного документа при DPI-масштабировании Windows, отличном от 100%. Не связана с логикой самого отчета или схемой компоновки данных — воспроизводится независимо от состава выбранных полей.
- **Серьезность:** S4 (низкая) — не влияет на корректность данных, только на визуальное отображение при конкретной конфигурации экрана.
- **Приоритет:** Низкий — для целей демонстрации есть обходной путь (см. ниже), доработка самого отчета не является блокирующей.
- **Статус:** Открыт, применяется обходное решение.
- **Комментарий / обходное решение:** Для контрольных проверок остатков используется штатный «Универсальный отчет» платформы, который не подвержен данной проблеме (выводит только табличную часть без встроенной диаграммы). Альтернативно — временное снижение масштаба экрана Windows до 100% на время формирования отчета устраняет проблему. Постоянное исправление (настройка ширины полей и/или формата ресурсов в схеме компоновки данных отчета) запланировано отдельным пунктом доработок.
