# Тест-кейсы: подсистема складского учета

Формат: ID, объект, метод, предусловия, шаги, ожидаемый результат. Фактический результат и ссылка на баг-репорт (если есть расхождение) фиксируются в колонке «Статус» по мере прогона.

## TC-01 — Приходная накладная: успешное проведение

- **Объект:** Документ «Приходная накладная»
- **Метод:** Позитивное, функциональное
- **Предусловия:** В справочнике «Номенклатура» есть товар, в справочнике «Склады» есть склад.
- **Шаги:** Создать новую приходную накладную, указать склад, добавить товар с количеством и ценой, провести документ.
- **Ожидаемый результат:** Документ проводится без ошибок; в регистре «ОстаткиНоменклатуры» появляется приходное движение на указанное количество по указанному складу.
- **Статус:** пройден

## TC-02 — Приходная накладная: заполнение на основании заказа поставщику

- **Объект:** Документ «Приходная накладная», обработчик `ОбработкаЗаполнения`
- **Метод:** Функциональное
- **Предусловия:** Существует проведенный документ «Заказ поставщику» со списком номенклатуры.
- **Шаги:** Создать приходную накладную на основании заказа поставщику.
- **Ожидаемый результат:** Поля «Контрагент», «Договор», «ВидЦены» и табличная часть автоматически заполняются данными из заказа.
- **Статус:** пройден

## TC-03 — Расходная накладная: успешная отгрузка при достаточном остатке

- **Объект:** Документ «Расходная накладная»
- **Метод:** Позитивное
- **Предусловия:** По товару на складе есть остаток не менее отгружаемого количества (создается через TC-01).
- **Шаги:** Создать расходную накладную, указать тот же склад и товар, количество меньше или равное остатку, провести.
- **Ожидаемый результат:** Документ проводится успешно; остаток по регистру уменьшается ровно на отгруженное количество; формируются движения по регистрам «Выручка», «Продажи», «ЗадолженностиКлиентов».
- **Статус:** пройден

## TC-04 — Расходная накладная: попытка отгрузки сверх остатка

- **Объект:** Документ «Расходная накладная», процедура `ОбработкаПроведения`
- **Метод:** Негативное, граничное
- **Предусловия:** Остаток товара на складе — известное конечное число (например, 10 шт.).
- **Шаги:** Создать расходную накладную, указать количество больше фактического остатка (например, 20 шт. при остатке 10), попытаться провести.
- **Ожидаемый результат:** Отказ в проведении (`Отказ = Истина`), пользователю выводится сообщение вида «Не хватает товара "<товар>" на складе "<склад>" в количестве <N> <ед.изм.>», остаток в регистре не изменяется.
- **Статус:** пройден — поведение соответствует ожидаемому, логика проверки остатков подтверждена

## TC-05 — Расходная накладная: расчет себестоимости по средневзвешенной цене

- **Объект:** Документ «Расходная накладная», запрос расчета себестоимости
- **Метод:** Функциональное
- **Предусловия:** По товару было несколько приходов по разной цене.
- **Шаги:** Провести расходную накладную на количество, включающее остатки от разных приходов.
- **Ожидаемый результат:** Себестоимость в движении регистра «Выручка» рассчитывается как средневзвешенная от стоимости остатка на момент проведения, без «увода в минус» суммовых остатков.
- **Статус:** пройден

## TC-06 — Загрузка курсов валют: успешный сценарий

- **Объект:** Общий модуль «РаботаСВалютами», процедура `ЗагрузитьКурсыВалют`
- **Метод:** Позитивное, интеграционное
- **Предусловия:** Есть сетевой доступ к www.cbr-xml-daily.ru.
- **Шаги:** Запустить процедуру загрузки курсов валют.
- **Ожидаемый результат:** Формируется документ «УстановкаКурсовВалют» на текущую дату; для валют, отсутствующих в справочнике «Валюты», автоматически создаются новые элементы; курс валюты рассчитывается корректно (обратная величина от значения ответа сервиса).
- **Статус:** пройден

## TC-07 — Загрузка курсов валют: недоступность сервиса

- **Объект:** Общий модуль «РаботаСВалютами»
- **Метод:** Негативное
- **Предусловия:** Сеть отключена или сервис недоступен.
- **Шаги:** Запустить процедуру загрузки курсов валют при отсутствии сетевого доступа.
- **Ожидаемый результат:** Исключение перехватывается, пользователю выводится сообщение «Произошла сетевая ошибка!», документ не формируется, аварийного завершения сеанса не происходит.
- **Статус:** пройден

## TC-08 — Получение цены номенклатуры: цена не установлена на дату

- **Объект:** Общий модуль «Вспомогательный», функция `ПолучитьЦенуНоменклатуры`
- **Метод:** Негативное, граничное
- **Предусловия:** По товару нет ни одной записи в регистре сведений «ЦеныНоменклатуры» на запрашиваемую дату и вид цены.
- **Шаги:** Вызвать функцию с товаром, для которого цена не установлена.
- **Ожидаемый результат:** Функция возвращает 0, исключение не возникает.
- **Статус:** пройден

## TC-09 — Отчет «Остатки товаров на складах»: корректность итогов

- **Объект:** Отчет «ОстаткиТоваровНаСкладах»
- **Метод:** Функциональное
- **Предусловия:** По нескольким товарам есть движения на складе.
- **Шаги:** Сформировать отчет за период, включающий все движения.
- **Ожидаемый результат:** Строка «Итого» равна сумме количеств по всем строкам детализации; данные совпадают с ручным подсчетом по регистру.
- **Статус:** пройден

## TC-10 — Отчет «Остатки товаров на складах»: отображение при увеличенном масштабе экрана

- **Объект:** Отчет «ОстаткиТоваровНаСкладах», форма отчета
- **Метод:** Негативное, UI
- **Предусловия:** Масштабирование экрана Windows установлено выше 100% (например, 175–200%, актуально для демонстрационной среды на Retina-дисплее).
- **Шаги:** Сформировать отчет с суммовыми значениями от шести знаков.
- **Ожидаемый результат:** Колонки «Цена» и «Сумма» отображают значения полностью.
- **Фактический результат:** При масштабе экрана выше 100% колонки «Цена» и «Сумма» отображаются как «####» — значения не помещаются, автоматический расчет ширины колонок платформой работает некорректно. При масштабе 100% отчет формируется корректно. Причина — известная особенность работы платформы 1С с нецелым масштабированием экрана Windows, не связана с логикой самого отчета.
- **Статус:** дефект найден, см. `bug-report.md` (BUG-01)

- **Статус:** пройден
